# 原有业务完全复原：剩余工作评估

评估日期：2026-09-01。

## 结论

当前项目完成的是“架构基座、MSS 1.3.7 双后台、存量表安全只读兼容面和
storefront bootstrap”，还不是原有业务完全复原。31 个业务验收场景关闭数仍为
0。源码归属是商城平台 50 个资源、租户平台 1 个支付资源，51 个通用兼容资源均
保持只读；商城设置四字段和会员等级专用流程已完成远端正式测试、生产构建及 MSS
1.3.7 全量源码门禁，但尚未完成隔离 PostgreSQL reconciliation、部署或验收。
前向权限迁移尚未在任何环境执行或部署，旧商品/物流数据也尚未按租户转换。列表、
详情、单元测试、构建或本地浏览器烟雾检查不能替代环境迁移、旧业务写流程、数据
迁移和系统验收。

阶段状态：Phase 0/1 已完成；Phase 2 控制面和 Phase 3 商城后台仅部分完成；
Phase 4 仅完成 bootstrap；Phase 5 已完成一次隔离快照导入及独立校验，但可重放
迁移、恢复/回滚、完整集群验收和切换尚未完成。阶段定义
以 [`roadmap.md`](../migration/roadmap.md) 为准。

- 商品分类模板、分类/价格导入导出、逐行错误报告和重复提交保护；订单、物流、
  库存导入因影响主链路仍属于 P0。
- 广告、功能圈、弹窗，以及图片、视频、外链、分类、商品、优惠券跳转。
- 所有新增专用页面、按钮、校验、错误、通知、导入报告和商家内容 fallback 的
  `zh-CN`/`en-US` 完整性；落实翻译数据模型和历史订单文案快照。
- 租户平台及完整业务页的内置浏览器复核。当前证据只覆盖商城只读兼容面的有限
  页面。

## P2：明确不作为首期阻断项

- 原生 App 已延期；首期客户端目标是 H5 和微信小程序。
- 第三种及更多语言不是首期范围；首期完整语言为 `zh-CN` 和 `en-US`。
- 旧系统中注释掉、空实现或不可达的退款/Dashboard 占位不机械复制；若要新增，
  需单独定义业务状态机和验收。
- 不要求像素级复刻旧 Vue 页面，但旧业务动作、数据语义、权限、审计和错误边界
  必须完整恢复。后台页面以 mss-boot-admin 的布局、设计令牌、表格、表单、反馈和
  状态交互为准；不引入第二套后台设计系统，也不复制旧页面结构。

## 前端实施约束

- 当前通用只读资源页是迁移期查看器，不扩展为承载所有业务的“万能编辑器”。有
  状态机、跨表副作用或领域校验的写流程使用聚焦的 MSS 风格业务页面。
- 业务页面、Hook、服务和类型模型保持单一职责；优先复用小而稳定的组件，避免
  大型配置驱动页面、重复路由/API 适配、无类型字段字典、魔法状态值和散落的兼容
  分支。
- 兼容适配层必须有唯一归属和可删除条件。验收关注业务语义、权限、错误状态、
  双语和可维护性，不把旧系统视觉一致性作为目标。

## 建议实施顺序与依赖

1. 开发数据库指纹、迁移工具、身份映射和可重放数据演练。
2. 持久化控制面、真实 reconciler、角色/schema/Secret 和双租户隔离。
3. MSS 身份迁移、171 权限及仓库数据范围。
4. 按租户导入商品/物流资料，再完成商城配置、商品可售、仓储/物流/支付安装。
5. 客户、营销、钱包和 ERP 基础。
6. 订单/支付/物流状态机、outbox、worker 和外部适配器。
7. 按契约实现 storefront API，再迁移 H5/小程序消费端页面。
8. 完成导入导出、首页内容和全域双语。
9. 在集群内关闭 31 个场景，完成 UI 复核与恢复演练后再讨论切换。

订单依赖商品、客户、仓库、库存、支付、物流和钱包；商城前台依赖这些后端状态
机。不能通过先补页面来宣称业务复原。每个工作包只有在代码、存量数据语义、
权限正反向测试、集群证据和对应验收场景同时成立后才算完成。
